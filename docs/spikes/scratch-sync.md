# Scratch sync spike

Automatic two-way scratch-file synchronization works between macOS and a GitHub
Codespace. Mutagen is a viable engine. Prefer an explicitly managed private port
forward for the transport; the ordinary GitHub CLI SSH proxy has lifecycle
behavior that is unsuitable for an unattended sync connection.

Measured on 2026-10-16: macOS arm64, Linux amd64, Mutagen `0.18.1`, GitHub CLI
`2.102.0`. Only synthetic files in new trial directories were synchronized.
The official Mutagen archive matched the vendor's SHA256 manifest.

## Observed results

| Check | Result |
|---|---|
| Initial remote agent deployment and session creation | Passed; 38.338 seconds |
| Automatic Mac-to-Codespace create | Passed; observed in 5.593 seconds |
| Automatic Codespace-to-Mac create | Passed; observed in 6.746 seconds |
| Edits, renames, ordinary file deletions | Passed in both directions |
| Nested paths, spaces, Unicode filename | Passed |
| 2 MiB binary | SHA256 matched at both endpoints |
| Concurrent, different edits to the same file | Both contents preserved; conflict appeared in status |
| Manual conflict resolution | Passed; original versions retained in separate files |
| Dropped SSH transport, offline edits on both sides | Automatic reconnect and catch-up in 16.810 seconds |
| `git add --all` with scratch payloads present | Only intended tracked files staged; payloads remained ignored |
| Files outside the sync root | Unchanged |
| Tracked scratch instructions | Excluded from sync and unchanged |
| Mutagen through a private loopback port forward | Passed in both directions |
| Guarded retries against an actually stopped Codespace | Three refusals, zero SSH executions; five API observations remained Shutdown |

Timing includes SSH commands used to observe or inject changes. These are trial
measurements, not isolated file-transfer benchmarks. Watcher tests used no manual
`flush` command. The reconnect test terminated the session's own SSH transport,
blocked new transport attempts, created different files at both ends, then
removed the block without invoking `resume` or `flush`.

An early reconnect attempt overlapped another test phase and invalidated that
attempt. The harness also initially searched for the wrong disconnected-status
text. Both were corrected, and conflict resolution and reconnect passed when
rerun sequentially. The retained private evidence includes the failed attempt.

## Folder contract

Commit `.scratch/README.md` and `.scratch/.gitignore`. The latter contains:

```gitignore
*
!.gitignore
!README.md
```

The folder therefore exists in new clones while working contents stay out of
ordinary commits. Explicitly ignore `/.gitignore` and `/README.md` in Mutagen:
Git manages those files. Mutagen's own ignore configuration is separate from
the folder's Git ignore rules; ignored working files synchronized successfully.

Proposed shared instruction for `AGENTS.md` and `CLAUDE.md`:

> Use `.scratch/` for temporary project inputs, experiments, investigation notes,
> and intermediate outputs needed across sessions. Do not commit its working
> contents or remove them without an explicit request. Move lasting code and
> documentation into the appropriate tracked directories. Access this folder
> explicitly when needed; ordinary Git-aware searches may omit its contents.

## Transport findings

The first live session used the OpenSSH configuration generated by
`gh codespace ssh --config`, a dedicated configuration file, and Mutagen's
`two-way-safe` mode. Mutagen deployed its Linux agent automatically. No complete
Mutagen package or additional Feature was needed in the container.

Stock `gh codespace ssh` can start a stopped Codespace. Its stdio transport also
enables traffic monitoring that feeds client-activity notifications. Ongoing
sync traffic can therefore interfere with idle shutdown. This is established
from the installed CLI version's [connection code](https://github.com/cli/cli/blob/v2.102.0/internal/codespaces/codespaces.go),
[SSH options](https://github.com/cli/cli/blob/v2.102.0/pkg/cmd/codespace/ssh.go),
[traffic monitor](https://github.com/cli/cli/blob/v2.102.0/internal/codespaces/portforwarder/port_forwarder.go),
and [activity heartbeat](https://github.com/cli/cli/blob/v2.102.0/internal/codespaces/rpc/invoker.go).
The trial did not wait for an actual idle timeout.

The second live session used `gh codespace ports forward` with its default
loopback binding, then ordinary OpenSSH to that local port. This also passed
two-way sync. The CLI's [port-forwarding implementation](https://github.com/cli/cli/blob/v2.102.0/pkg/cmd/codespace/ports.go)
leaves activity tracking disabled, which avoids that particular activity-reporting
mechanism. Mutagen reconnects to localhost rather than invoking GitHub CLI each
time. Once the forwarder is down, those retries cannot themselves start a Codespace.
Actual idle-timeout behavior still needs a separate end-to-end check.

Creating the forwarder can itself start a stopped Codespace. A controller must
separate an explicitly requested start from background reconnection. A state
check before invoking GitHub CLI is a useful prototype guard, but has a race if
the Codespace stops between the check and the connection. A strict guarantee
against automatic starts requires a transport/controller that cannot issue a
start request; the stock CLI's connection helper can issue one.

## Recommended integration

- Keep the folder convention independent of whether syncing is enabled.
- Run the controller on the Mac. Offer sync explicitly in the wizard and remember
  the repository, local folder, selected Codespace, and account locally.
- Bind each pairing to the repository and exact Codespace identity. Replacing a
  Codespace or selecting a different worktree must require a reviewed rebind.
- Expose `devcontainer:scratch:up`, `down`, and `status` tasks. Own the forwarding
  process and Mutagen session; do not edit unrelated SSH configuration or sessions.
- Use `two-way-safe`, a private loopback forward, and a dedicated known-hosts file.
  Show pending changes, disconnection, and conflicts in status.
- Keep remote scratch contents under `/workspaces` for
  [rebuild persistence](https://docs.github.com/en/codespaces/about-codespaces/deep-dive).
- Add recoverable history before treating this as storage for important material.
  Ordinary deletions propagated in the trial. Synchronization alone is not backup.

## Remaining rollout checks

Physical Mac sleep, container rebuild, Codespace replacement, actual idle timeout,
case-colliding filenames, and recovery from deletion were not tested. The trial
does not establish company software approval or data-handling permission.

## Cleanup

Both trial sessions were terminated, the isolated Mutagen daemon and private
forwarder stopped, and local synthetic files and downloaded binaries removed.
The remote trial files, agent binary, and agent cache were removed after checking
the agent's hash against the vendor package. The existing project repository
retained its original commit and clean Git status. The Codespace was restored to
its original stopped state. No login service was registered.

The trial did not enable a wizard feature or change project agent instructions.
Local receipts and the experimental harness are retained privately under the
canonical checkout's ignored `.superpowers/scratch-sync-spike/` directory.
